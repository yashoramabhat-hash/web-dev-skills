## Step 3 — The loop

1. **Scope** — target, stack, blast radius, what "done" means.
2. **Recon the code** — read the project, find the real entry points, existing patterns and data flow. Do not guess the architecture.
3. **Design** — schema first, then endpoints, then auth, then the surface.
4. **Build** — matching the project's existing conventions. Include error paths, not just happy paths.
5. **Verify** — run the tests, then `semgrep` / `codeql` for static findings.
6. **Report** — what changed, what was tested, what was not, and any residual risk.

### Non-negotiables
- Confirm the stack before proposing an approach — read the project, do not assume.
- Design the schema before the endpoints.
- Validate input and rate-limit at the boundary.
- Never log secrets, tokens or PII.
- Match the project's existing patterns over generic best practice.
- Migrations must be reversible; expand-contract, never a destructive rename in one step.
- Ship observability with the feature — logs, metrics, error paths.
